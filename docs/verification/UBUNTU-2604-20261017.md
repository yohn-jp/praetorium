## Live defects corrected and verification limits

The first Build start exposed invalid `--publish-port`, conflicting duplicate
AppArmor executable attachments, and a capability bounding set that prevented
subordinate UID mapping. The corrected implementation uses `--publish`, reuses
Ubuntu's packaged RootlessKit profile and keeps the non-root host process's
ambient capabilities empty. `--copy-up=/etc` preserves isolated resolver
files. The global AppArmor userns restriction stayed enabled.

Before the first real build, only this run's failed bootstrap account,
generated files and empty cache were reconciled. `buildctl du` reported 0 B,
all owned service processes were stopped, and only then was that new cache
removed. OS/user data, proxy and new validation PKI were preserved. Corrected
full bootstrap then completed normally and wrote its own role marker.

The real network build subsequently exposed the missing internal proxy CIDR
in the cgroup allowlist. That rule was fixed in the production unit renderer,
then installed without deleting the now-populated cache and verified with
actual approved/denied requests. No fixture substitutes for these host tests.

Frozen pnpm 11.18.0 install, full `pnpm check`, 16 Python regression tests
including real OpenSSL certificates, and independent read-only review passed.
The complete Python suite also ran on the actual Ubuntu Build guest at
`7ae4a140d24a87070217bec0a8b1094f1e0f869f` with Python 3.14.4 and OpenSSL
3.5.5: 16 tests passed, no skips. The command was
`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -v`.
The reviewer findings about BuildKit version enforcement and proxy resolution
were fixed before final integration. Ubuntu 24.04 remains allowed and has
regression coverage; no live 24.04 guest was used in this validation.
