## Runtime transition

`packages/application/src/lifecycle` owns the provider-neutral state machine. It resolves an admitted immutable target before retiring the current runtime, reserves a fresh capacity epoch before quiesce, requires a request-bound timely producer receipt, persists each recovery point before effects, and waits for a complete all-epoch provider census to prove the prior writer absent. Lease expiry, a ready Deployment, producer self-reported image identity and incomplete Pod lists do not prove writer termination or artifact identity. Fresh readiness combines the actual child manifest digest from the running Pod with producer-reported repository/epoch/composition/module state and real positive/negative auth probe evidence before route activation.

`apps/provisioner` composes that state machine with the T03 operation HTTP client, append-only fenced lifecycle checkpoints, the T07 Kubernetes provider, capacity reservations, private Scriptorium status/quiesce/resume calls and the existing worker, health and metrics surfaces. Control credentials are requested from the fenced Control Plane per action and exact body digest; no long-lived runtime token is embedded in configuration. The `start` script runs the built Node entry point. Runtime configuration is static and validated at startup; producer assignments remain structured metadata and are not copied into invented environment variables.

## Current proof boundary

- Quiesce receipts are bound to operation, instance, epoch, observation time and receive time. Unsafe, unknown or late outcomes resume only the matching operation/epoch and block retirement when confirmation is missing.
- Stop and replacement release reservations only after T03 accepts the durable provider writer-absence proof for the exact prior runtime.
- Capacity admission uses a fresh T07 observation and requires both aggregate free capacity and one node that fits the target profile before the old runtime is quiesced.
- Same-digest redeploy still retires epoch N and starts a new epoch. The old runtime remains running while artifact resolution is pending.
- The worker does not treat control-plane lease expiration as workload termination.

The producer has not published how its structured `RuntimeAssignment` reaches the container, and the S02 grant-probe transport is still missing. No environment-variable or ConfigMap ABI is inferred. Until Praetorium can assign a runtime and perform and record a valid grant, wrong-repository grant, wrong-epoch grant and invalid service-credential probe against a real ready producer, route activation is unavailable. The executable composes the real worker and providers but keeps readiness false and does not claim operations while either proof source is absent.

The current T03 operation projection also has no typed idle-stop reason/feed and no persisted rollback-compatibility evidence. The 15-minute default/configurable idle decision exists as a provider-neutral application policy, but it is not scheduled against production runtime observations. Automatic rollback compatibility therefore fails closed. These require typed shared contracts; T09 does not infer an idle operation from an untyped stop or guess rollback safety from matching image digests.
