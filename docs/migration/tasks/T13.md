# T13 — Legacy migration and Platform recovery

Authority: [Platform architecture §8](../../architecture/PLATFORM.md#8-migration-recovery-and-public-repository), [migration plan T13](../PLAN.md#t13--legacy-migration-and-platform-recovery), and [coverage ledger A10/A12](../COVERAGE.json). The package is an explicit operator tool and is not wired into normal service startup.

## Implemented acceptance unit

- `plugins/legacy-recovery` provides an offline `import-plan` CLI over a versioned Platform export, producer manifests, and an optional target-origin map. It groups on immutable repository ID, splits a multi-repository legacy instance into repository bindings, deduplicates the same repository across exports, and preserves source instance/user/origin/release/audit/producer export IDs as provenance. A conflicting locator or GitHub installation, missing producer record, target-origin collision, or pending/unknown producer state is reported as a blocking conflict.
- Each planned binding has `targetInstanceId: null` until the target Control Plane creates a binding. The plan always says that old browser storage, ACL grants, and access tokens are not migrated and GitHub authorization must be revalidated. Unpublished or unknown producer data keeps the binding blocked and identifies old data as retained. Planning is deterministic and performs no writes.
- Metadata archives contain the remote D1 SQL export, migration checksum manifest, and platform config. The payload is encrypted with scrypt-derived AES-256-GCM; the format and KDF/cipher header are authenticated, and file size/checksum metadata is verified after decryption. Restore authenticates before touching the target, requires a new absolute destination outside the checkout, applies restrictive file modes, and never runs SQL.
- `d1-backup` requires explicit `--remote`, checks Wrangler D1 identity and complete export output, creates the authenticated encrypted archive, uploads it to off-host Restic, and emits a secret-free receipt. Credentials are split between Wrangler and Restic process environments. `legacy-d1-restore` remains compatible with source-format D1 Restic snapshots, verifies their manifest/checksums, and stages plaintext SQL without executing it.
- `pvc-backup` reuses the source Restic snapshot tag and data identity fields from an operator-supplied read-only `/data` mount, verifies the unique snapshot's host/path/tag, and performs a full Restic data check. It only creates/reuses a backup snapshot. Existing PVCs and unpublished application work remain untouched.

## Source mapping and remaining gates

The implementation was based only on the read-only `/tmp/praetorium-campaign-source` snapshot. Source recovery behavior inspected:

- `scripts/recovery/d1-restic.mjs` plus `docs/operations/d1-recovery.md`: explicit Wrangler remote D1 info/export, manifest/checksum staging, off-host Restic, isolated SQL staging without execution.
- `packages/runtime/src/kubernetes/provider.ts`, `packages/runtime/src/types.ts`, and `apps/provisioner/src/runtime-executor.ts`: retained-PVC identity/fencing, read-only `/data` recovery Job, tagged Restic snapshot verification, and full-data check before accepting a recovery point.
- `infrastructure/kubernetes/infrastructure/policies/provisioner-backup-job.yaml`: admission restrictions on the recovery Job and exact PVC claim.
- `infrastructure/nixos/modules/backup.nix`: off-host Restic schedule for persistent data.

No source tree or production environment was changed; no Actions workflow was added or run. No real Wrangler, Restic, D1, Kubernetes, or source PVC operation was run. The package's PVC CLI verifies the mounted path is read-only and checks the caller-supplied source UID in the Restic tag/receipt, but it has no Kubernetes API binding of its own. Production invocation must remain inside the source Provisioner's exact-PVC recovery boundary or an operator-verified equivalent. The real isolated D1 restore, key escrow, producer checkpoint resolution, target binding cutover, and old PVC/work retirement remain unperformed and require separate operator action.
