# T14 browser-entry acceptance

`tests/e2e/browser-entry.test.mjs` is the fixed-runner acceptance for the real Gateway, Instance Access, repository UI, and connected Scriptorium runtime. It does not start a mock application or treat the local Gateway security probe as acceptance. The fixed verifier supplies `PATH`, `HOME`, `USERPROFILE`, `XDG_CONFIG_HOME`, `PRAETORIUM_T14_INVENTORY_PATH`, `PRAETORIUM_T14_CATEGORY`, and `PRAETORIUM_T14_RESULT_PATH`, plus `SystemRoot` when present.

The gate requires an explicitly owned, disposable, non-production environment with stable HTTPS Gateway and instance origins, an installed test GitHub App, a repository the authenticated user can maintain, a stopped configured instance, a real browser executable, and a GitHub-only Playwright storage-state file. The browser state must contain GitHub-domain cookies only and no origin storage; Platform sessions are created by the actual OAuth callback. The disposable Scriptorium profile must contain only that owned project, whose remote tree has exactly one scene at `manuscript/vol-1/ch-1/scene-1.md`; the browser journey edits only that manuscript. The public application host is stable by numeric repository ID: the owner-only config declares `instance.hostnameSuffix`, and the runner requires `instance.origin` to equal `https://<repository.id>.<hostnameSuffix>`. Internal `instance.id` remains a separate runtime/binding identifier and is never used to derive the public host.

Set `resources.browser-entry.reference` in the fixed-runner inventory to the absolute path of an owner-only JSON file. That file has exactly these top-level fields:

```text
schemaVersion: 1
inventory: { inventoryId, ownerIdentity, environmentName, expiresAt }
gateway: { origin, expectedUserId }
repository: { id, fullName }
instance: { id, origin, hostnameSuffix, applicationHeading }
browser: { executablePath, githubStorageStatePath }
producer: { revision, runtimeBaseDigest }
producerAdmission: { sourceJobId, releaseId, controlPlaneOrigin, adminCredentialPath }
writeProbe: { path, body }
selection: { releasePolicy, releaseId, moduleIds, resourceProfileId }
mcp: { clientName, requiredTools }
timeouts: { loginSeconds, wakeSeconds, configurationSeconds, redeploySeconds, mcpSeconds }
```

Use numeric GitHub repository IDs, exact origins without URL paths, the owner-attested application hostname suffix, the actual producer app heading, and a private storage-state file containing only GitHub authentication. `instance.hostnameSuffix` must be a lowercase DNS suffix without a scheme, path, port, or placeholder domain; the origin must exactly bind the numeric repository ID to that suffix. `producer` contains the expected current source commit and Runtime Base digest. `producerAdmission` points to the exact admitted Source job and release, the HTTPS Control Plane origin, and an owner-only file holding the dedicated Control Plane admin credential. The credential file must be a regular file owned by the runner user with no group or other permissions; the runner trims trailing whitespace, uses the credential only in the `X-Control-Plane-Admin-Auth` header, never follows redirects with it, and never logs it. The runner reads only the fixed Source job detail and release status GET endpoints under the owner lease. It requires the job to be admitted with the expected source commit and linked release ID, and the release to be available with the expected Runtime Base digest. Control Plane admission binds that candidate to the signed producer catalog and proof; the runner does not claim to independently read or reverify catalog fields or cryptographic proof. Those checks remain in the Control Plane/OCI admission gate. The historical `docs/migration/PRODUCER-STATUS.json` ledger remains provenance history; its old producer tuple and S01–S05 entries are not the current Hosted admission fence. The browser journey itself exercises the capabilities it needs. No Git tree hash is required because this live admission readback does not expose one.

The configured selection must be supported by the connected producer and differ from the currently deployed module set. `writeProbe.path` must be the actual disposable producer's side-effecting API or MCP write route and `body` its bounded JSON request. The test sends it once while the dashboard reports the instance stopped, requires Instance Access to answer `503 INSTANCE_STARTING` with `Retry-After: 5`, and disables redirects. The disposable environment owner is responsible for selecting a probe whose effect is safe if a concurrently started instance wins the race.

The test follows the actual GitHub OAuth redirect/callback and checks `/api/session`, host-only session and CSRF cookies, selecting the authorized repository from the live repository list, one-use handoff and replay rejection, direct stopped-origin bookmark wake, and stable application origin. It performs a separate real public-client DCR and read-scope S256 PKCE consent, exchanges the code, rejects an invalid bearer, initializes MCP, and lists tools over the stable instance origin. It invokes no MCP tool and reads no manuscript through MCP. Required read-only tool names come from the owner-only input; client IDs, codes, and tokens remain in memory and are not evidence output. In the connected Scriptorium UI it selects the sole owned scene, edits one bounded marker line, waits for browser draft durability, creates a local Checkpoint, saves through the UI to GitHub, verifies the confirmed commit and manuscript path through pinned remote reads, reloads the application, and confirms the saved text and state. It then exercises UI preview, observes an in-progress build while the old digest remains current and ready, checks the existing application during that build, verifies deployment digest/module selection, same-image redeploy, UI re-entry, and refresh CSRF/cookie rotation. The owner lease is checked before each outbound operation and immediately before write, wake, and mutation actions; browser-originated requests are aborted at lease expiry. Independent GitHub readback remains an integration-owner proof after the runner's producer save; the runner's pinned remote reads alone are not described as independent GitHub verification. A unit fixture only verifies the guard's match/mismatch/failure behavior and is not Hosted evidence.

The test exits zero only after every assertion succeeds. On a missing prerequisite it exits nonzero and writes the fixed-runner's strict result sidecar at `$HOME/runner-result.json` as `BLOCKED` with one of the bounded reason codes. An acceptance assertion exits nonzero as `FAILED`. A nonzero process without a valid sidecar remains `NOT_CHECKED`/failure under the fixed runner; no skip is converted to success. A publicly admitted source-release candidate is now recorded in the migration evidence, while canary and full Hosted gates remain separate. Candidate admission alone does not verify this browser journey; the fixed runner must still pass against matching producer evidence and the owned test environment.
