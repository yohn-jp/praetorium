# T07 — Kubernetes runtime and capacity

Status: package implementation complete and locally verified; no Kubernetes cluster proof has been run.

## Source extraction

The implementation extracts the production REST transport/client, error mapping, ownership helpers, capacity reader, and runtime observation/reconciliation path from the immutable Arcadia Platform snapshot pinned by the migration plan (`b96a03a8734bfff2e5b965e6966007c45a2c7dc9`). The source paths are `packages/runtime/src/{errors,labels,naming,types}.ts` and `packages/runtime/src/kubernetes/{client,error-mapper,types,provider,loom-renderer}.ts`. The Praetorium renderer is adapted to the repository-scoped Scriptorium contract and omits legacy Jobs, PVCs and recovery/deletion APIs.

## Acceptance evidence

The package implements the provider and verifies at package level that:

- tenant resources carry deterministic instance, repository, runtime-epoch, and cluster ownership;
- runtime workspaces use bounded disk-backed ephemeral storage, and the workload has one writer, a non-root identity, read-only root filesystem, dropped capabilities, and no mounted Kubernetes token;
- ownership and generation conflicts fail closed, every Kubernetes mutation invokes `beforeEffect`, and replacement remains pending until actual old writer Pods are absent;
- capacity derives from complete paginated Node and cluster-wide Pod observations, records both resourceVersions and exact represented reservation IDs through the D1 `recordCapacitySnapshot` port, and fails closed unless the returned D1 epoch matches; pending reservations remain deducted, while `ensureRunning` may add back only its exact current reservation after matching cluster/instance/repository/epoch/generation/resources;
- the runtime package contains no legacy PVC deletion/recovery path.

## Integration notes

The T07 worktree is based on Praetorium main `f81f13c942af243e8612d68bbdb6462167554966` plus shared foundation commit `7c77e4dfe59799e7429f0a4c3d5ab7a3e09aae37`. The T07 package owns its Kubernetes adapter types and exposes the runtime provider/capacity ports; root manifests and the neutral contract package remain root-owned.

Runtime endpoints are rendered separately from the workload. `activateEndpoint` requires fresh positive application and auth probe records plus a matching ready Pod whose container `imageID` ends in the admitted platform-manifest digest. The producer has not declared a versioned assignment-to-container transport ABI; the package does not invent environment variables or ConfigMap paths. A started workload without that producer integration is not application readiness evidence, and the lifecycle adapter must not activate its route without its real positive probes.

The provider's `RuntimeRelease.releaseId` accepts a bounded opaque deployment revision ID; immutable image reference and selected platform-manifest digest remain separate inputs from the artifact admission service.

The package has not been run against a Kubernetes cluster. Actual CNI policy behavior, in-cluster provisioner RBAC, architecture-specific `imageID` format, Pod termination evidence and D1/Kubernetes timing require the isolated T14 environment before deployment readiness can be claimed.
