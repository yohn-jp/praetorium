## Migration and rollback boundary

The intended apply path is `scripts/deploy-platform.mjs --apply`: complete local/remote preflight, apply canonical D1 migrations, read back full migration history, then roll out immutable K3s images and Cloudflare Workers in the declared order. `scripts/deploy-cloudflare.mjs --preflight` is read-only; `--migrate` changes D1 only. No production migration or rollout was attempted for this candidate.

`0007_source_release_recovery.sql` is additive and must remain applied during code rollback. An older Control Plane version is a rollback candidate only after checking its D1 read compatibility and current bindings; the old checkout's migration readback rejects `0007`, so use current tooling for preflight and do not rerun an older deployment script as a rollback shortcut. Gateway authorization has a stricter, separate floor: after epoch revocation is enabled, never roll back to pre-epoch Gateway code such as the `eb292a4` baseline, because it ignores the credential cutoff and can revive revoked credentials. Only a recorded post-cutoff Gateway version that also preserves future fencing, with the same Durable Object state, may be considered; bounded timestamp materialization (at most 100 records per alarm) does not prove global completion. Keep prior immutable K3s image digests available and verify writer exclusion/quiesce before runtime rollback. The complete production rollback path, including cross-plane restore and compatibility checks, remains NOT_CHECKED.
