The `@praetorium/scriptorium` consumer adapter is implemented against the frozen `scriptorium-build/v1` and `scriptorium-platform/v1` schemas in `@praetorium/contracts`. It parses only strict versioned metadata. This completes the adapter implementation; it does not certify a producer image or the full T04 real-image gate.

## Adapter behavior

`normalizeComposition` parses the shared catalog, validates graph references and semantic module versions, rejects dependency cycles and declared conflicts, and checks that the producer resolver returns exactly the requested transitive dependency closure. It calculates minimum resource demand as base resources plus each selected module's exclusive demand plus each referenced shared group once, rejects overflow/unknown groups/undersized profiles, and constructs the shared canonical `BuildInput` with required source digest and sorted module identities. Resource profile selection remains outside the build key.

`runtimeApplicationRequirements` maps the producer-declared listener, liveness/readiness/metadata/shutdown paths, timeout, and fixed status/quiesce/resume paths. `runtimeAuthenticationPolicy` exposes the assignment's separate expected user-grant and control-service issuer/JWKS/audience policies as probe inputs; their presence does not prove either verifier is active. `assertRuntimeStatusBoundToAssignment` checks the app's self-reported repository, instance, epoch, image/composition digests, and enabled modules against the assignment. That report is not image proof: registry and CRI observations must corroborate the actual artifact. Auth readiness still needs real positive and negative HTTP probes. The quiesce schema binds each response to operation, instance, and epoch and rejects `safe` while any active job/mutation, pending checkpoint, or uncertain publication remains.
