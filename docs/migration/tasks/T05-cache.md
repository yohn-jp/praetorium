## D1 behavior and adapter

Praetorium's current schema has one admitted artifact per build key (`idx_artifacts_one_admitted_per_build`) and keeps the signed statement, signature and verification data on the artifact row. `D1BuildStore.recordReport` is the canonical admission writer: if a later verified report conflicts, it leaves the earlier row admitted, records `builds.failure_json.code = 'ARTIFACT_CONFLICT'`, marks the build failed and clears `builds.artifact_digest`. The cache adapter treats that failure as a permanent cache quarantine, even when the old admitted row still exists for a deployment already using it. It never changes an artifact digest or promotes a rejected row.

`D1ArtifactCacheStore` in `packages/persistence/src/d1/artifact-cache-store.ts` implements the application cache port over those rows. `findByBuildKey` reconstructs verified-artifact records from persisted build input, statement, signature and verification data; it returns conflict before an admitted cache record when D1 carries the conflict failure. If an artifact row is absent, the adapter inserts one only when the persisted build is succeeded, its artifact digest matches the candidate, and its active attempt is succeeded with that same manifest digest. Identical verified output can append attestation evidence and update a monotonic `lastHitAt` in the existing `verification_json`, using a compare-and-set batch. A divergent verified output is recorded as cache conflict metadata in that same JSON field; the admitted OCI identity and D1 deployment references remain untouched. A missing or failed build cannot create cache admission.

`getGarbageCollectionSnapshot()` returns cache entries and live-reference pins from a single SQL read. Running pins come from non-null `logical_instances.current_artifact_digest`; desired pins come from `desired_artifact_digest`. While an update or redeploy is active, every prior admitted revision for that instance is pinned: `operations` does not persist the exact `LifecycleOperation.current` revision, so narrowing the pin to one prior generation could miss the actual rollback artifact after the observed revision changes. `ARTIFACT_CONFLICT` builds and cache-quarantined rows are excluded from eviction candidates. `listArtifactUseReferences()` is also available when a caller needs only pins. The existing application `planCacheGarbageCollection` remains the bounded LRU/minimum-age planner. A snapshot can inform a reviewable plan; it does not authorize later OCI deletion because a reference may change after the read.

## Consumer wiring and proof limits

Sol can export `D1ArtifactCacheStore` from `packages/persistence/src/d1/index.ts` and pass it with the D1 binding to `BuildArtifactCache`. Use `BuildArtifactCache.lookup(buildKey)` before reusing an admitted result so signer policy and live registry reachability are rechecked. Let `D1BuildStore` persist the first successful admission, then record additional cache admission evidence through the cache store. For planning, pass the entries and references from one `getGarbageCollectionSnapshot()` result to `planCacheGarbageCollection`; keep registry deletion behind a separately reviewed, reference-fenced owner path.

The new tests use Node SQLite with the repository's current `apps/control-plane/migrations/0001_repository_platform.sql`. They verify D1 row reconstruction, monotonic attestations/hit time, persistent conflict quarantine, and running/desired/rollback reference selection. This is adapter/schema evidence only: it is not a Cloudflare D1 contention test, an OCI delete test, GHCR proof, or producer acceptance. No source data, public registry, production database, or registry deletion was touched.
