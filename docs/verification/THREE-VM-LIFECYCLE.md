The Kubernetes renderer now requires tenant Scriptorium Deployments to match `praetorium.io/node-role=runtime`. This leaves a tenant writer Pending when no Runtime Agent is labeled and prevents tenant scheduling onto the Management K3s Server. The change does not alter instance, repository, generation, runtime-epoch, or release selectors and annotations. The renderer test checks the required affinity.

Infra confirmed the matching host contract: label the Management Server `praetorium.io/node-role=management` and taint it `praetorium.io/node-role=management:NoSchedule`; label the Runtime Agent `praetorium.io/node-role=runtime`. The live cluster has not been converted to that topology.
