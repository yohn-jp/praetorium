# T14 browser acceptance

The browser gate is mapped to a fixed runner path in `scripts/verify-integration.mjs`. It remains BLOCKED until production Gateway and Instance Access bundles, an integrated entry route, and an explicitly owned stable test origin are available. `gateway-worker-security.partial.test.mjs` is a separate local source-execution probe: it bundles the committed Gateway Worker, uses local Miniflare KV/DO bindings and cached Chromium over loopback HTTPS, and checks a narrow set of redirect, session, nonce, CSRF and logging behaviors. Duplicate-cookie probes are direct requests to the same Miniflare Worker because Chromium cannot naturally emit duplicate `__Host-` cookies. It does not verify Instance Access, an owned stable origin, successful GitHub App login, a producer artifact or recovery, and it does not satisfy or change the fixed browser-entry gate.

The e2e runner must use the inventory's owner-attested disposable test origin and cover direct bookmark wake, login and one-use handoff, cookie/CSRF behavior, API retry behavior without replaying writes, and re-entry after a real producer restart. The inventory cannot supply commands or test code.
