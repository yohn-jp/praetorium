# Runtime authority and credential reuse: local D1 evidence

The repeatable runner is [runtime-authority-d1.mjs](runtime-authority-d1.mjs); its full output, query plans, initial row snapshots, exact source hashes, and baseline identity are in [runtime-authority-d1.local-evidence.json](runtime-authority-d1.local-evidence.json). The baseline is commit `f03e239b9f9430208a0fc3b4f050d48d3b15406d`. Run `node tests/benchmarks/runtime-authority-d1.mjs` after the current sources and migration are integrated in this worktree.

The production-cardinality seed has 2 bindings, 13 operations, 169 checkpoints, and 354 credentials. The stress seed has 81 bindings, 257 operations, 2,050 checkpoints, and 5,201 credentials. Each side gets a fresh Miniflare D1 and the same deterministic seed; the runner checks matching table/status snapshots before measuring. Both sides then perform 100 repetitions of the same runtime and permission tuple. The after workload is 100 warmed exact-scope reuse hits against one seeded credential. A real first mint or renewal is excluded; the legacy side simulates the old credential registration SQL with synthetic ciphertext. Repository lookup, access and authorization checks, signing, and GitHub requests are unchanged and not measured. All rows and metadata are local synthetic Miniflare data.

The old route performs three current-authority reads per request: the broker's runtime check, the runtime check inside its repository-binding reader, and the Control Plane registration check. It also purges up to 64 expired credentials, inserts a new credential, and reads it back. The benchmark counts those three authority reads and three credential SQL statements; the separate repository-binding lookup is outside the measured workload. The current path does one current-authority read and one `findReusable` query per warm request. Its repository-binding wrapper reuses the already-read authority result, and it skips per-request purge, insert, and readback on a hit. Thus the measured path falls from six to two D1 statements and from three to two authority evaluations per request.

The legacy `WITH candidates` plan is a compound candidate query with `UNION ALL`, a temporary B-tree for ranking, repository-wide operation-index reads, checkpoint lookups, and correlated proof, retirement, resume, and credential checks. The new authority query uses direct lookups for the repository binding, logical instance, reservation, and optional current operation. The reuse query uses the existing `runtime_git_credentials_retirement` index on `(repository_id, runtime_epoch, status, expires_at)`, with remaining scope fields checked against candidate rows. Token readback uses the token primary key. The bounded expiry purge has no expiry index and its plan scans credentials and sorts by expiry. No index was added: per-request cleanup is removed, the existing scheduled purge deletes at most 64 rows every five minutes, and local evidence does not establish a production-scale index benefit versus maintaining it on every credential write.

The scheduled purge is reported separately from request measurements. After the reuse workload it read 722 rows and deleted 64 in the production-cardinality seed, and read 6,493 rows and deleted 64 in the stress seed. These are local metadata values, not production cost estimates. Read-only Cloudflare listing identified the `praetorium-platform` D1 database across two accounts. A remote read-only SQL request returned D1 API error 7500; Insights provided no usable query data. Hosted D1 plans and analytics therefore remain `NOT_CHECKED`. Producer, registry, and browser acceptance are also `NOT_CHECKED`.
