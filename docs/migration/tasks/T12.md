# T12 — Sanitized infrastructure and disposable preflight

T12 provides sanitized NixOS host-role modules, static Flux controller and platform ownership, Kubernetes service/ingress/TLS templates, Worker D1/KV/Durable Object/service binding templates, a rootless remote BuildKit host configuration, strict inventories, and explicit plan/preflight/apply procedures. Worker bindings follow the current package contracts: one Control Plane D1 database, Gateway KV plus its two Durable Objects, and the Gateway-to-Control-Plane service binding.

The local Kubernetes apply path is limited to a named disposable Kind cluster created by the same inventory. It verifies node ownership labels and the derived `kind-<name>` context, refuses missing inputs/placeholders, and applies only shared static resources. Flux's platform reconciliation starts suspended; dynamic per-instance namespaces and workloads are excluded from static Flux ownership. The provisioner ServiceAccount has no RBAC until T07's exact runtime resource operations can be reviewed.

T14's inventory is stored separately at `infrastructure/test/acceptance-inventory.json`, has all seven required resource categories in `missing` state, and explicitly marks its owner identity as an unresolved operator placeholder. The integration preflight is read-only, does not consult kubeconfig, and reports missing categories as `BLOCKED` / `NOT_CHECKED` with no side effects.

Validation: Nix module checks passed; kubectl 1.36.1 / Kustomize 5.8.1 rendered the base, Flux controllers, deployment overlay, and disposable overlay; Node syntax checks passed; the strict inventory validator and integration plan ran. The infrastructure preflight found Kind 0.31.0 and kubectl/Kustomize through explicitly configured Nix-store executables, then correctly blocked on the absent HTTPS Control Plane/Gateway endpoints, BuildKit inputs, registry repositories, and immutable image digests. The Worker plan reports the not-yet-present T03/T08 Worker entrypoints. No cluster, Worker, secret, or production environment was changed. This is an implementation/preflight handoff, not a live runtime certification or production deployment.
