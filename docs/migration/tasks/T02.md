Provider-specific GitHub App OAuth, REST access, installation JWT/token, access intersection and webhook handling live under `plugins/github`. Auth grants use T01's numeric repository ID, instance ID, runtime epoch, permission set, session revision and current binding authorization revision.

`createGitHubAppPlugin` composes the Gateway-facing OAuth provider, encrypted-token sink seam, repository access provider, and runtime/repository/epoch credential broker. User permissions are intersected with the exact active App installation's permissions and operator policy. The fresh access result carries the canonical HTTPS instance origin from a trusted `instanceOriginFor` resolver; MCP, handoff and refresh grants use that authority result instead of request-supplied audiences. Publish takes no actor ID: the broker verifies the Gateway's strict ES256 receipt against exact repository, instance, epoch, operation, payload digest and time; it derives the actor from `sub`, matches the receipt authorization revision to the current binding, and checks current GitHub write access. Installation tokens are restricted to one repository and Contents `read` or `write`. Webhook signatures are checked over exact raw bytes before delivery deduplication. No static token fallback exists.
