# T08 — Authenticated entry, stable-origin handoff and wake

Owner paths: `apps/gateway` except `src/ui` (T10), `apps/instance-access`, and this task packet.

Authorities: [platform contract](../../architecture/PLATFORM.md), [Scriptorium producer contract](../../architecture/SCRIPTORIUM-CONTRACT.md), and [migration plan](../PLAN.md). This packet records the acceptance unit for T08; it does not certify a provider, producer or deployed Worker.

## Acceptance

- Gateway authenticates through the GitHub App user-authorization flow, retains the shared PKCE, CSRF, session, refresh, key/JWKS, logout and MCP credential lifecycle, and persists authoritative auth state through configured Durable Objects. KV holds only digest lookup indexes, best-effort limits and public signing-key records.
- Repository listing comes from the current GitHub access provider. A repository entry is available only when current user authorization intersects the active App installation and service policy.
- Opening a repository revalidates current GitHub access, resolves the durable repository binding atomically, and asks the instance service to make that single repository instance run. Repeated opens coalesce. No user-owned duplicate instance or host-derived binding is created.
- Entry is sent to the stable instance HTTPS origin. The Gateway issues a one-use handoff code with a 60-second maximum lifetime. Instance Access accepts the code only in a same-origin form POST at `/_platform/handoff`; the code is bound to the exact host, repository binding, instance and runtime epoch before exchange.
- Instance Access keeps access, refresh and CSRF cookies host-only, Secure and HttpOnly where applicable. Refresh and logout return through the Gateway session authority and enforce CSRF. No reusable GitHub or application credential appears in URLs, browser storage, logs or the handoff page.
- Direct HTML navigation to a stopped origin reaches Gateway authentication/authorization and the existing binding's wake path. The stable origin remains available during startup. API and MCP callers receive a bounded startup/maintenance response with `Retry-After`; the Platform does not buffer or replay their request bodies.
- Gateway control calls carry only authenticated metadata. Manuscript bodies and streams continue directly between the browser/MCP client and Scriptorium.
- Production composition uses Hono and refuses to route requests when required provider settings, bindings, secrets, keys or exact origin/hostname configuration are missing or invalid. There is no in-memory, fake-provider or static-token production fallback.

The runtime Git credential HTTP route is mounted with a strict request schema
and rate limiting. The Gateway composition constructs the real broker when
its separate GitHub App private key and trusted Control Plane issuer are
configured. It verifies short-lived runtime identity JWTs against the public
Control Plane JWKS and rechecks the current D1-backed runtime binding. Only
the trusted post-absence target may bootstrap a new writer; browser access
continues to use the observed current epoch while a new configuration builds.
The App token issuer limits Git access to the assigned numeric repository;
publishing also requires an actor-bound mutation receipt and fresh user write
authorization. Control Plane reads enforce body limits and deadlines even
when a stream ignores abort. Public JWKS contains no private key material.

The Control Plane exposes Gateway-authenticated binding metadata and
Provisioner-authenticated identity issuance, using a separate operator key.
Target issuance additionally checks the current operation lease and persisted
old-writer absence proof. The actual Wrangler bundle and owned local D1/DO
runner verify route separation, public key shape and absence of a binding for
an unassigned instance. These are Platform boundary proofs. The producer's
service-token/assignment transport and renewable credential provider remain
missing S03 contracts; no runtime interoperability or actual App token renewal
is claimed. Missing keys or bindings leave brokerage unavailable.

## Focused evidence and environment gates

Gateway and Instance Access package tests cover browser-bound OAuth state,
strict Control Plane response parsing, session/CSRF checks, fresh repository
authorization, mutation receipt scoping, direct entry readiness, exact-host
body-only handoff, host-only cookies, refresh rotation, logout revocation,
invalid host/origin/form rejection, and startup/API body non-replay. The real
Worker entry points and scripts are wired through the production Hono
composition. These tests use isolated adapters; they do not claim concurrent
Cloudflare service behavior.

Real GitHub App accounts and repositories, a running Control Plane with D1,
simultaneous desired-state requests, producer S02 runtime interoperability,
deployed Cloudflare bindings, and browser/ingress behavior remain T14
environment gates. No unit fixture certifies those gates.

## Source behavior retained or replaced

Reuse the campaign source's provider-neutral OAuth/PKCE, session and CSRF lifecycle, MCP credential functions, one-use handoff/refresh primitives, Durable Object auth stores, key/JWKS support, error/security headers and request redaction. Replace source behavior that treated a user's instance list as ownership, opened only already-running instances, or assumed a per-user instance. Keep T10's SSR portal isolated under `apps/gateway/src/ui` and mount its handler from the Gateway composition.
