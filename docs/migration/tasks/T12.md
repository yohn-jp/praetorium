# T12 — Sanitized infrastructure and disposable preflight

T12 provides sanitized NixOS host-role modules, static Flux controller and platform ownership, Kubernetes service/ingress/TLS templates, Worker D1/KV/Durable Object/service binding templates, a rootless remote BuildKit host configuration, strict inventories, and explicit plan/preflight/apply procedures. Worker bindings match the current entrypoints: one Control Plane D1 database and RepositoryCoordinator, Gateway KV plus USER_AUTH_STATE and EPHEMERAL_CODES, and the Gateway-to-Control-Plane service binding. Worker templates use compatibility date 2026-07-30 and the Control Plane build policy is generated from strict, public inventory values.

The local Kubernetes apply path is limited to a named disposable Kind cluster created by the same inventory. It verifies node ownership labels and the derived `kind-<name>` context, refuses missing inputs/placeholders, and applies only shared static resources. Flux's platform reconciliation starts suspended; dynamic per-instance namespaces and workloads are excluded from static Flux ownership. T07 renders the private per-tenant NetworkPolicy using the actual namespace and workload labels and producer-declared application port. T12's static Provisioner ServiceAccount has no RBAC binding. The integrated Node Provisioner stays unready and claims no operations while producer S03 assignment and S02 grant-probe transports are unavailable.

T14's inventory is stored separately at `infrastructure/test/acceptance-inventory.json`, has all seven required resource categories in `missing` state, and explicitly marks its owner identity as an unresolved operator placeholder. The integration preflight is read-only, does not consult kubeconfig, and reports missing categories as `BLOCKED` / `NOT_CHECKED` with no side effects.

Validation: Node syntax checks, strict inventory validation, and four standalone Kustomize renders pass. Infrastructure preflight correctly blocks because Kind and the checked-in inventory's operator inputs are absent; Worker preflight confirms all three current Control Plane migrations and valid Worker templates, then blocks on the same explicit input gaps. The full `corepack pnpm@11.18.0 check` passes. The required frozen install is blocked at this base because `apps/provisioner/package.json` names `@praetorium/kubernetes` while the root-owned lockfile lacks that workspace importer; PNPM's non-frozen check install regenerated the importer, which was reverted to keep the lockfile out of T12 scope. Nix flake evaluation passes, but its syntax-check derivation could not build because the host cannot create `/nix/var/nix/profiles`. No cluster, Worker, secret, or production environment was changed. This is an implementation/preflight handoff, not a live runtime certification or production deployment.
