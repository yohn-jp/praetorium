# T05 — GHCR, artifact admission, and build cache

## Implemented acceptance unit

`@praetorium/ghcr` supplies an allowlisted OCI Distribution client, source-release Sigstore verifier, operator-key builder-signature verifier, and pre-sign candidate verifier. Repository identities are namespaced paths only; registry origin and credentials are configured separately. Mutable tags can be resolved once to a digest, while all subsequent verification requires a lowercase `sha256` digest. OCI root and selected child manifests are hashed, descriptor length/media type is checked, image config bytes bind the requested OS/architecture, and every layer is downloaded by digest and streamed through an incremental SHA-256 check. Operators must configure aggregate image-layer bytes (`maxImageLayerBytes`), an overall image-verification timeout (`maxImageVerificationMs`), and a per-request timeout including body reads (`maxRegistryRequestMs`). The candidate verifier requires and propagates the build-attempt `AbortSignal`; cancellation reaches token exchange, manifests, config, composition blob, layer streams, and smoke inspection. Manifest, blob, token, and provenance bodies are read through bounded streams. Redirects and URL credentials are rejected.

Pull and publish credentials are distinct registry-only credentials. Pull tokens request only `pull`; publish tokens request `pull,push` only for an explicit derived-output repository. No GitHub App token or repository token enters the registry client. The copied Sigstore public-good trust root matches the inspected source file at SHA-256 `6494e21ea73fa7ee769f85f57d5a3e6a08725eae1e38c755fc3517c9e6bc0b66`. Source provenance requires a configured signer identity allowlist and an in-toto subject matching the requested immutable digest. Derived artifacts use the separate Ed25519 operator-key path from `@praetorium/contracts`; no keyless Actions identity is accepted.

`GhcrCandidateVerifier.verifyUnsignedCandidate(candidate, approvedOutput, signal)` requires the Control Plane's approved `{ registryHost: "ghcr.io", repository }` and build-attempt signal alongside the untrusted candidate. It refuses a candidate from any other origin or repository before registry access or signing, then binds the reported root image and composition digest to persisted `BuildInput`/build key, validates the shared `scriptorium-composition/v1` schema and exact module closure, and requires an injected inspector to compare actual server/browser entries, module closure, native dependency identities, and the declared health smoke against the digest-pinned image. It returns a canonical `BuilderArtifactStatement` only after those checks pass. The package deliberately includes no container runtime or default inspector. T06 must inject a host implementation that inspects and runs the immutable image; a producer declaration or unit fixture is not proof.

`ArtifactAdmissionService` verifies the operator signature, recomputes the key against authoritative persisted `BuildInput`, re-fetches and hashes OCI/composition content, checks selected platform identity and shared composition bindings, then returns a `VerifiedArtifact` with the immutable `repository@digest` and persisted input. `BuildArtifactCache` only stores a verified result. Its store port requires an atomic absent/admitted/conflict transition by build key: identical outputs append evidence, divergent verified outputs become permanently conflicted, and later reports cannot clear the conflict. A cache hit rechecks signer policy, build input, composition bytes, and registry reachability. The pure GC planner retains artifacts referenced by running, desired, or rollback revisions and only proposes deletions with no retained or live references.

## Source mapping and verification

The only source tree inspected was the immutable Arcadia Platform snapshot pinned by [PLAN.md](../PLAN.md) at `b96a03a8734bfff2e5b965e6966007c45a2c7dc9`. GHCR behavior was compared with `apps/control-plane/src/adapters/ghcr/ghcr-registry-client.ts`; Sigstore verification and the vendored public-good trust root were compared with `apps/control-plane/src/adapters/sigstore/sigstore-provenance-verifier.ts` and its `assets/trusted-root.json`. Source files were read only.

Fresh package verification on the T05 worktree passed:

```sh
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/contracts build
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/ghcr typecheck
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/ghcr test
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/ghcr build
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/application typecheck
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/application test
PATH=/tmp/praetorium-bin:$PATH pnpm --filter @praetorium/application build
```

The focused suites passed **31/31 GHCR plugin tests** and **5/5 application admission/cache tests**. They cover mutable tag movement, changed child and layer bytes, wrong config platform, missing layers, configured aggregate layer bounds, bounded chunked metadata responses, stalled-header/body timeouts, caller cancellation, separate registry credentials, bad/revoked operator signatures, exact BuildInput/composition and approved output-repository binding, injected closure/smoke failures, missing cache content, same-key conflict, identity-field rejection, and live-reference GC protection. Registry and inspector fixtures are unit-test doubles, not live image or host execution evidence.

No disposable OCI registry was available in the environment: `docker`, `podman`, `nerdctl`, `buildkitd`, and `registry` were not installed. No registry endpoint or dedicated disposable GHCR credentials were configured. No public package push or GHCR write was attempted. The current Scriptorium source has not published S01 composition metadata or a verified image, and no production image inspector/smoke runner was available. Therefore real push/pull, registry round-trip, Scriptorium closure/smoke, and live admission remain blocked; the implementation does not claim those gates passed. Release catalog persistence and rollout channels remain with their owning Control Plane tasks.
