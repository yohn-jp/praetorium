# T12 — Sanitized infrastructure and disposable preflight

T12 provides sanitized NixOS host-role modules, static Flux controller and platform ownership, Kubernetes service/ingress/TLS templates, Worker D1/KV/Durable Object/service binding templates, a rootless remote BuildKit host configuration, strict inventories, and explicit plan/preflight/apply procedures. Worker bindings match the current entrypoints: one Control Plane D1 database and RepositoryCoordinator, Gateway KV plus USER_AUTH_STATE and EPHEMERAL_CODES, Control Plane-to-Gateway `GATEWAY_SERVICE`, and Gateway-to-Control-Plane `CONTROL_PLANE`. Worker templates use compatibility date 2026-07-30; the Control Plane scheduled handler runs every five minutes. Build and release policies are generated only from complete, strict public inventory values. The build inventory includes four required cache-retention operator inputs (`maxBytes`, `maxEntries`, `minAgeMs`, and `maxEvictions`); each remains null until explicitly set, blocking `BUILD_POLICY_JSON` generation. Retention planning is advisory and pin-aware, and does not enable OCI deletion or claim storage was reclaimed.

The Worker plan/preflight lists Gateway's webhook HMAC secret and GitHub App PEM independently. Control Plane requires its runtime-identity signing secret and lists the separate runtime-control signing secret for its optional route. Both Control Plane and Gateway require the same 32–4096 non-space printable ASCII `RUNTIME_CREDENTIAL_RETIREMENT_AUTH` value; it remains distinct from Gateway auth, Provisioner, Build Worker, and release-operator credentials, and is not required by the Node Provisioner. The migration preflight includes `0004_runtime_git_credentials.sql`. The D1 registry stores Gateway-encrypted credential blobs and metadata for known runtime Git credentials. At a fenced old-runtime quiescing checkpoint, Control Plane asks Gateway to revoke matching known credentials; Gateway's provider only clears the retirement barrier after GitHub returns `204` and the authoritative records are no longer pending. A `401`, rate limit, network error, or deadline keeps the operation blocked for retry or until the credential's recorded expiry has passed. Lease expiry does not establish writer absence. `RELEASE_POLICY_JSON` is optional and generated only from a fully supplied operator-owned, disposable canary binding; the checked-in inventory intentionally leaves it disabled. `RELEASE_OPERATOR_TOKEN` is a separate secret, distinct from Gateway, Build Worker and Provisioner service credentials. T11 admission remains blocked on S01 immutable producer metadata, and canary evidence/promotion remain blocked on authenticated S02/S05 UI, API, MCP and persistence observations. Neither the local inventory nor unit tests are producer acceptance evidence.

The local Kubernetes apply path is limited to a named disposable Kind cluster created by the same inventory. It verifies node ownership labels and the derived `kind-<name>` context, refuses missing inputs/placeholders, and applies only shared static resources. Flux's platform reconciliation starts suspended; dynamic per-instance namespaces and workloads are excluded from static Flux ownership. T07 renders the private per-tenant NetworkPolicy using the actual namespace and workload labels and producer-declared application port. The static base now includes the minimal Provisioner bootstrap and tenant-role graph, namespace/RoleBinding/runtime ownership admission, tenant Pod constraints and exact current route/network shapes. The provider creates restricted PSA namespaces and rejects missing, weakened or pinned-old security labels without changing an existing namespace. Static system NetworkPolicies use explicit operator API/private-origin endpoints and named runtime destination ports; they remain unverified against a real policy-enforcing CNI. The integrated Node Provisioner stays unready and claims no operations while producer S03 assignment and S02 grant-probe transports are unavailable.

T14's inventory is stored separately at `infrastructure/test/acceptance-inventory.json`, has all seven required resource categories in `missing` state, and explicitly marks its owner identity as an unresolved operator placeholder. The integration preflight is read-only, does not consult kubeconfig, and reports missing categories as `BLOCKED` / `NOT_CHECKED` with no side effects.

Validation: the focused Worker deployment and retention-input tests cover unset, boundary, invalid, and partially configured limits; planning remains effect-free and withholds `BUILD_POLICY_JSON` unless every retention value is supplied. A fresh frozen pnpm install and full `corepack pnpm@11.18.0 check` pass on this committed base. Worker preflight validates all four Control Plane migrations and both service-binding templates, then remains blocked on missing owned disposable inputs; it reports no secret inspection and makes no remote call. The four Kustomize renders and Nix evaluations are unchanged by this delta; prior T12 evidence records the renders and flake evaluation passing, while the Nix syntax-check derivation could not build because the host could not create `/nix/var/nix/profiles`. No cluster, Worker, secret, or production environment was changed. This is an implementation/preflight handoff, not a live runtime certification or production deployment.
